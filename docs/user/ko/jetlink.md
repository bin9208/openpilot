# Android Jetlink 실험 앱

대상은 갤럭시 탭 S9 울트라 12GB(Android 15 이상)와 comma 3X입니다. 앱은 arm64 Android 9 이상에서 설치 가능하도록 빌드하지만, 다른 기기 호환성과 대상 기기의 실측은 별도 검증 사항입니다. 현재 단계는 모델·연결 검증용이며 차량 사용 승인이 아닙니다.

## 설치와 모델 가져오기

1. 제공된 APK와 SHA-256을 대조한 뒤 APK를 탭에서 엽니다. 파일 앱의 외부 앱 설치 권한이 필요할 수 있습니다.
2. `Carrot Jetlink` → **모델** → **모델 패키지 ZIP 가져오기**에서 준비된 패키지를 선택합니다. 모델은 APK에 포함되지 않으며 내부 앱 저장소에 검증 후 저장됩니다. 가져오기는 모델 용량 외 임시 공간이 필요합니다.
3. 패키지는 `manifest.json`, `model.onnx`, 선택적 `benchmark.frames.bin` 순서의 ZIP입니다. 경로·크기·SHA-256·입출력 형상·상태 연결을 검사합니다. CTV3의 원본 바이트를 보존한 stateful 패키지를 사용합니다. queued 모델은 수치 일치 검증 미완료로 거부합니다.
4. CPU가 초기 기준입니다. NNAPI 선택은 실행 제공자 요청이며 전체 모델의 NPU 가속을 보장하지 않습니다. 실패하거나 일부 연산이 CPU에서 실행될 수 있습니다.

업데이트할 때 앱을 삭제하거나 데이터를 지우지 마세요. 같은 서명으로 만든 APK를 덮어 설치해야 모델 데이터가 유지됩니다. CI 임시 debug APK는 실행마다 서명이 달라질 수 있으므로 배포용 로컬 APK와 섞어 업데이트하지 마세요.

## 정차 상태 벤치마크

**벤치마크** → **100프레임 속도 측정**를 실행합니다. 화면을 켜 둔 채 기다리세요. 준비·워밍업 후 실제 ONNX Runtime 추론 시간을 측정합니다. 입력은 패키지의 합성 프레임을 반복하거나 검은 이미지와 고정 문맥을 사용합니다. 평균/p50/p95/p99/최대값과 50ms 초과 횟수를 표시합니다. 백분위는 최근 2,000개, 평균·최대·초과 횟수는 전체 실행 기준입니다.

**출력 비교 ZIP 저장 (벤치마크 후)**로 첫 입력 묶음의 실제 출력을 저장합니다. 패키지 입력은 최대 100프레임이며 초과하면 가져오기를 거부합니다. ZIP을 PC에서 풀고 `tools.jetlink_model.compare`로 동일 입력의 PC 기준 기록과 비교합니다. **진단** → **진단 보고서 저장**으로 기기/모델/요청 제공자/성능·발열 정보를 저장합니다. 측정값은 실행 시작 당시 모델·제공자를 유지하며 나중에 선택을 바꿔도 바뀌지 않습니다. 발열·메모리는 내보내는 시점의 값입니다. 카메라 영상이나 위치는 진단 파일에 기록하지 않습니다.

측정 시간에는 C3X 카메라 변환과 전체 USB 왕복이 포함되지 않습니다. APK 빌드·합성 입력 성공은 실제 탭 성능, 30분 발열 또는 차량 검증을 대신하지 않습니다.

## USB 연결과 중지

C3X에는 Jetlink 통합(#47)이 포함된 브랜치가 필요합니다. 앱만 설치해서는 연결되지 않습니다. Carrot Web의 `시스템 → Jetlink 외부 모델 → Jetlink 모드`를 오프로드에서 1(Shadow)로 설정합니다. 기본값은 0이며 관리 프로세스 재시작·재부팅 시 0으로 돌아갑니다. USB 3 데이터 케이블로 연결하고, C3X가 Jetlink vendor gadget(1209:0001)을 준비한 다음 앱의 **상태** → **comma USB 연결**을 누르고 USB 권한을 허용합니다. 앱은 알림을 표시하는 연결 서비스를 사용합니다.

권한을 거부하거나 케이블을 분리하면 수동으로 다시 연결해야 합니다. **중지** 또는 알림의 **중지**로 서비스를 종료합니다. 재부팅/프로세스 종료 후 자동 연결하지 않습니다. 발열 단계 SEVERE 이상은 작업을 중단하며 식힌 뒤 다시 시도합니다. 메모리 부족·모델 오류는 상태 화면에 표시합니다. 엔진 `ready`는 주행 허용 상태가 아닙니다.

실기 검증 전 확인 항목: APK 설치/회전, 모델 가져오기, CPU 및 NNAPI 출력 비교, USB 권한 거부·분리·재연결, 30분 Shadow와 열화 상태, C3X 전체 50ms 지연·소실 시 제어 해제. 이슈 #44/#45/#46/#47의 실기 항목은 결과가 나올 때까지 열어 둡니다.

## C3X 제어 전환과 검증 경계

Shadow에서는 내부 모델이 제어를 담당하며 외부 결과를 기다리느라 내부 출력을 지연시키지 않습니다. 외부 활성 중에도 내부 모델은 매 프레임 실행하여 상태를 유지합니다. USB 소유 프로세스의 정지/느린 응답은 별도 50ms 통신 제한으로 격리합니다. 전체 예산은 C3X warp 시작부터 외부 응답·해석·발행 직전까지이며 앱 단독 수치와 다릅니다.

모드 2는 활성 요청입니다. 현재 제공물에는 통과한 실기 검증 기록이 없으므로 내부 모델을 유지합니다. 검증 프로필은 원본과 실제 실행 파일의 SHA-256, 태블릿 모델, Android API, 요청 백엔드, 앱/ORT 버전, warp 계약과 수치 비교·최소 30분 전체 지연/유실 증거를 묶습니다. 앱 0.1.1부터 이 기기 정보를 handshake로 전달하며 버전·백엔드를 바꾸면 이전 검증은 일치하지 않습니다. 벤치마크 성공만으로 활성 플래그를 만들지 마세요.

활성 중 첫 timeout/분리/잘못된 프레임/NaN은 외부 출력을 폐기하고 소실 상태를 유지합니다. `외부 모델 소실`에 해당하는 no-entry/soft-disable 경로를 사용하며, AlwaysLateral 단독 조향도 소실 상태를 우회하지 않습니다. 내부 모델 성공이나 재연결만으로 소실 상태를 지우지 않습니다. 정차·크루즈/조향 해제 후 0 또는 준비된 1로 확인하고 다시 2를 요청해야 합니다. 오래된 프레임의 유효성을 새 프레임처럼 바꾸지 않습니다.

USB 오류 복구를 위해 주행 중 gadget을 재구성하지 않습니다. 오프로드에서 0 → 1로 재준비하고 앱도 다시 연결합니다. 커널 I/O가 멈춰 해제되지 않으면 정차 상태에서 기기를 재시작해야 할 수 있습니다. `JetlinkStatus`는 준비/오류 상태이며 frame 로그의 `modelV2.jetlink`와 `drivingModelData.jetlink`에 출처·소실·세션·측정값을 남깁니다. C3X QCOM 실기 빌드, 실제 USB 속도, 카메라 픽셀 비교 및 주행 수용은 아직 별도 검증 대상입니다.

C3X 초기 지원은 원본 바이트가 보존된 CTV3만 허용합니다. 앱이 가져온 모델의 실행 파일 해시가 원본과 다르거나 handshake에 해시가 없으면 연결 준비를 거부합니다. 같은 원본 이름·형상을 가진 다른 변환 파일에 기존 검증 기록을 재사용하지 않습니다.
