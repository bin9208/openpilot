# Jetlink C3X Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** C3X가 Android Jetlink를 Off/Shadow/Active로 사용하고 소실 시 명시적으로 해제·복귀한다 (#47).
**Architecture:** USB owner/client, warp/model adapter, mode/loss state machine을 분리한다. 기존 camera/parser/control 경계를 보존하고 모델 소실을 native 성공으로 숨기지 않는다.
**Tech Stack:** Python3.12, tinygrad, cereal, existing selfdrived events, pytest/replay, Jetlink pinned Python transport.
**Spec:** [승인 설계](../specs/2026-09-29-jetlink-android-design.md).

## Global Constraints

[전체 Global Constraints](2026-09-29-jetlink-android.md#global-constraints)를 적용한다.
기존 모델/pose 유효성·운전자 감시·panda 정책은 보존. USB gadget 변경은 offroad에만 수행.
Jetlink 상태를 기존 UsbGpuActive/Loading과 혼합하지 않는다. 같은 포트의 eGPU와 동시 시작 금지.
새 schema/event 번호는 각 enum/struct의 다음 미사용 ordinal을 검사하여 끝에 추가하고 기존 번호는 변경하지 않는다.

## Task C3: Shadow/Active 전환과 소실 해제

**Interfaces:** `Transition.update(mode:Mode, ready:bool, validated:bool, controls:ControlState, outcome:Outcome) -> Decision`.
Mode=OFF/SHADOW/ACTIVE_REQUEST, ControlState={standstill,cruise_enabled,lateral_active,enabled};
Outcome=NONE/VALID/LOST. Decision={source:NATIVE|JETLINK,phase,loss_latched,reset_required}.
`validated`는 해당 모델·backend·기기 조합의 parity/performance 승인 상태이며 READY와 다르다.
Params `JetlinkMode`의 값 0/1/2=Off/Shadow/활성 요청, 기본0. ACTIVE_REQUEST는 런타임 ACTIVE와 다르다.

- [ ] transition/event tests 작성: `test_shadow_never_changes_control`, `test_ready_without_validation_stays_native`, `test_lateral_only_blocks_switch`, `test_single_late_frame_latches_loss`, `test_native_success_does_not_clear_loss`, `test_reconnect_needs_inactive_stop`, `test_owner_death_no_auto_reenable`.
  Assertions: Shadow 항상 NATIVE; ready&&!validated NATIVE; lateral_active true에서 전환0회; LOST 이후 native 성공에도 loss=true; 재접속 READY.
- [ ] C3 파일과 기존 selfdrived state machine 검사를 실행해 신규 구현 부재 실패를 확인한다.
- [ ] 아래 전이표를 구현하고 status를 session generation/frame_id와 함께 기록한다. loss 정보는 frame의 모델 출처와 함께 전달하여 별도 느린 Params polling만으로 해제를 결정하지 않는다.

| 조건 | 출력/상태 | 제어 이벤트 |
|---|---|---|
| OFF 또는 SHADOW | native; Shadow 결과는 진단만 | Jetlink 실패로 native 제어를 바꾸지 않음 |
| 준비 또는 검증 미완료 | native, PREPARING/READY | 외부 활성 불허 |
| READY+validated+정차+cruise/lateral 해제 | 다음 새 frame에서 ACTIVE, queues reset | 직접 자동 engage하지 않음 |
| ACTIVE 응답이 같은 frame/shape/finite이며 전체50ms 이내 | Jetlink 유효 출력 | 기존 제어 |
| ACTIVE 최초 timeout/분리/NaN/frame mismatch | LOST latch, 외부 결과 폐기, native로 복귀 시도 | enabled/lateral-active면 soft-disable + no-entry; loss 지속 |
| native 복귀도 실패/무효 | 기존 invalid/missing-output 처리를 보존 | 기존 즉시/soft-disable 우선순위를 약화하지 않음 |
| 재연결 또는 다음 frame native 성공 | READY/NATIVE, loss 유지 | 연결 복구만으로 해제 취소 금지 |
| 제어 모두 해제+정차에서 실패 확인/재준비 완료 | latch 해제 가능, READY | 새 활성 전환 조건 다시 평가 |
